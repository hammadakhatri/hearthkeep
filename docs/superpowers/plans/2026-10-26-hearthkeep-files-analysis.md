# Hearthkeep Phase 3: Files, Analysis and Devices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner attach files (or bring them from chosen folders on the PC) to a chat, ask questions answered by model-written Python run in a locked-down Docker sandbox, see the answers as findings cards with interactive charts and checked numbers, send results to their own devices, and manage devices, folders and start at login.

**Architecture:** Chat files are checked by content on the server (stdlib only) and again by the real parsers inside the sandbox, then stored under the chat. A `python` tool runs each script in a fresh container (no network, read-only files, tmpfs output streamed back as a tar), and the server validates every result, chart spec and file before saving the run. A number checker compares every number in each reply of a chat with files against the runs' reported values. Sending creates per-device tray items plus an optional payload-free web push.

**Tech Stack:** Phase 1–2 stack (Python 3.12+/uv, FastAPI, httpx, cryptography, pytest; React 18 + TS, Vitest). Docker Desktop for the sandbox. New web dependencies: Vega-Lite (vega, vega-lite, vega-embed, vega-interpreter) and qrcode-generator. No new server runtime dependency.

**Spec:** docs/superpowers/specs/2026-10-26-hearthkeep-phase-3-design.md (kept local, not in the public repo). Earlier plans: `docs/superpowers/plans/2026-10-26-hearthkeep-foundation.md`, `docs/superpowers/plans/2026-10-26-hearthkeep-models-images.md` (their Global Constraints still apply).

## Global Constraints

- Everything from the Phase 1 and Phase 2 plans' Global Constraints still binds: 127.0.0.1 only, local models only, nothing personal in the repo (privacy scan on every commit), no model tool that changes settings, permissions, devices or anything outside the workspace, the model never approves its own requests, secrets never in prompts/logs/audit, every HTTP client uses `trust_env=False`, always dark, works at phone width, respects reduced motion, **no AI attribution in commits**.
- **New dependencies (version floors):** web `vega` >= 6.1.2, `vega-lite` >= 6.1.0, `vega-embed` >= 7.0.2, `vega-interpreter` >= 2.0.0 (the CSP has no `unsafe-eval`, so Vega runs with `ast: true` + the interpreter), `qrcode-generator` >= 1.4.4. Server: none (VAPID signing uses `cryptography`; zip/CFB/PDF checks use the stdlib). The sandbox's Python libraries exist only in the sandbox Dockerfile, pinned with `==` and `--require-hashes`, at least: `pandas` 2.3.1, `numpy` 2.3.1, `scipy` 1.16.0, `openpyxl` 3.1.5, `xlrd` 2.0.2, `pdfplumber` 0.11.7 (brings `pypdfium2`, `pdfminer.six`, `Pillow`), plus test-only `pytest` 8.4 and `pypdf` 5.0; base image `python:3.12-slim-bookworm` pinned by `@sha256:` digest (looked up at implementation time).
- **Chat files:** kinds `csv`, `xlsx`, `xls`, `pdf`, `txt`, `json`; type decided by content (magic bytes + parse check), never by extension. At most **5 files per message**, **50 MB per file** (enforced while reading). `.xlsm` and any workbook with macros (`xl/vbaProject.bin`, `_VBA_PROJECT_CUR`) are refused. An xlsx whose entries unpack to more than **1 GiB** is refused. Formulas are read as stored values, only inside the sandbox.
- **Storage:** `<data>/workspace/chats/<chat-id>/files/<file-id>.<ext>`; runs in `<data>/workspace/chats/<chat-id>/runs/<run-id>/` (`files/<output-id>.<ext>`); sandbox job folders in `<data>/runtime/sandbox/jobs/<run-id>/` (removed after each run). Chat ids are `[0-9a-f]{32}`; every other id is `token_urlsafe(12)` and accepted only if it matches `[A-Za-z0-9_-]{1,32}`.
- **Original file names** are stored (`chat_files.name`) and returned only by session-protected endpoints. They never appear in the audit log or server logs; audit records id, type and bytes. The local model sees them in the chat's file list.
- **Message lines:** `Attached file: {id}` (one per file, exact, like Phase 2's `Attached photo: {id}`).
- **Sandbox container (exact):** image `hearthkeep-sandbox:<12-hex content hash>`; one container per run; `--rm --network none --read-only --user 10001:10001 --cap-drop ALL --security-opt no-new-privileges --memory 4g --memory-swap 4g --cpus 2 --pids-limit 256 --tmpfs /tmp:rw,nosuid,nodev,noexec,size=268435456 --mount type=tmpfs,destination=/out,tmpfs-size=268435456`, the chat's `files/` folder bind-mounted **read-only** at `/data`, the job folder read-only at `/job`; never `--gpus`, never the Docker socket, never the data folder, secrets or the owner's folders. Container limit **120 s** (script limit 110 s inside), printed output kept up to **256 KB**, output tar up to 300 MB and 200 members.
- **Without Docker** the `python` level is forced to Ask (existing `effective_level`), and the runner **never runs code on the host**: an approved call without Docker returns the plain "needs Docker" message. The image is built only by `hearthkeep sandbox build --data <data>` (one-time download, documented).
- **Every analysis run is saved:** script, printed output, results, outputs, status, run time.
- **Three kinds of number** in replies of a chat with files: **computed** (matches a value reported by a run of this chat), **read from the document** (matches only a document value; label exactly `read from page N, not computed`), **unverified** (matches nothing; marked, with a note). Dates and counts are numbers. Numbers in the owner's question of that turn and in the chat's file names are exempt. Applies to every assistant reply, the at-a-glance reply and summaries sent to devices.
- **Charts:** Vega-Lite JSON emitted by the sandbox and validated on the server before storing: ≤ 1 MB serialized, ≤ 5,000 rows per inline dataset, ≤ 20,000 rows in total, depth ≤ 20; inline `values` only; no `url`, `href`, `datasets`, `usermeta`, `loader` or `$ref` keys, no `image` mark, no string starting with a URL scheme (`http:`, `https:`, `//`, `data:`, `file:`, `javascript:`, `ftp:`) except an allowed `$schema`. Rendered offline from the app bundle (no CDN), with a loader that refuses every load; PNG export on the device.
- **Push:** payload-free web push (no body at all), VAPID ES256 with the private key in the secret store under `vapid_private_key`; one HTTPS POST to the browser's endpoint, hosts limited to `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `web.push.apple.com` and `*.notify.windows.com`, `trust_env=False`, no redirects, 10 s timeout, headers `TTL: 86400`, `Urgency: normal`. The notification text is exactly `A file is ready in Hearthkeep`. Opt-in per device. Sending to the owner's own devices is **Look**.
- **Level keys:** `python` (Look, sandboxed, default Allowed; also used by `read_pages`), `files` (Look, default Allowed), `send` (Look, new default Allowed).
- **Step-up purposes** gain `add_folder` (adding an allowed folder) and `delete` (deleting a chat or a file; bound to a target `chat:<id>` or `file:<id>`). Removing a folder, removing a device, renaming a device and signing out other sessions need only the session.
- **Copy (exact):** password `This file is password-protected. Remove the password and attach it again.`; sandbox facts `ran in a sandbox · no internet · read-only files`; card sections `How I got this`, `Download rows`, `At a glance`, `Sent to you`.
- **Start at login:** Windows Task Scheduler task `Hearthkeep`, at logon of the current user, no window (`pythonw.exe -m hearthkeep serve`), logs to `<data>/logs/hearthkeep.log`; command `hearthkeep startup enable|disable|status --data <data>`. The web app only displays the state and the command.
- **Not in this phase:** Google Drive, searching inside documents, installing packages or network from Python, editing the owner's files, file expiry, GPU in the sandbox.

## Review Focus

1. **A bank statement PDF encrypted with only an owner password** (it opens without a password, as many statements do) → accepted and readable; only a PDF that needs a password to open is refused with the exact password message. (Task 2: `test_inspect_owner_password_only_pdf_opens`, `test_inspect_user_password_pdf_refused`.)
2. **A CSV saved by Excel with a BOM, semicolons and decimal commas** → accepted at attach as CSV, and `hk.read` gives the real column names (no `﻿` in the first) and numeric amounts. (Task 1: `test_csv_with_bom_and_semicolons_is_accepted`; Task 2: `test_read_csv_bom_semicolon_decimal_comma`.)
3. **A headline number written as "1.2k", "31%", "£4,210.50", "−3" or "12–24 March"** → matched to the run's value within the precision written; a wrong one is unverified. (Task 6: `test_formats_match_reported_values`.)
4. **A runaway script that prints endlessly** → stopped at the time limit, printed output cut at 256 KB with a note, the run saved as timed out, and the chat carries on. (Task 4: `test_runaway_print_is_cut_and_run_ends`.)
5. **A symlink or junction inside an allowed folder pointing outside it (or at the data folder)** → never listed by search; read and bring refuse it. (Task 8: `test_symlink_or_junction_escape_refused`.)

- Detection rules: `%PDF-` within the first 1024 bytes and `%%EOF` in the last 64 KB → pdf (else `damaged`). `PK\x03\x04` → zip: `xl/workbook.xml` present → xlsx; `xl/vbaProject.bin` or `macroEnabled` in `[Content_Types].xml` → `macros`; sum of `file_size` > `MAX_XLSX_UNPACKED` → `too_large_to_open`; any other zip → `unsupported`. CFB magic `D0 CF 11 E0 A1 B1 1A E1` → `cfb_stream_names`: `EncryptedPackage` → `password_protected`; `_VBA_PROJECT_CUR` → `macros`; `Workbook` or `Book` → xls; else `unsupported`. Otherwise text if the first 64 KB has no NUL (UTF-16 with BOM allowed) and decodes as UTF-8/UTF-8-BOM/UTF-16-BOM, falling back to cp1252: claimed `.json` (or unknown extension and it parses) → json via `json.loads` (failure → `invalid_json`); claimed `.txt` → txt; else csv. Binary kinds must match a claimed `.xlsx/.xls/.pdf` extension (else `mismatch`); a text file claiming `.xlsx/.xls/.pdf` → `mismatch`; claimed `.xlsm` → `macros`.
- Copy: `unsupported` "Hearthkeep can't read that file. Attach a CSV, Excel (.xlsx or .xls), PDF, text or JSON file."; `mismatch` "That file's name says {ext}, but its contents aren't. Check the file and attach it again."; `macros` "Excel files with macros can't be attached. Save it as .xlsx without macros and attach it again."; `password_protected` the Global Constraints text; `too_large_to_open` "That spreadsheet is too large to open (over 1 GB once unpacked)."; `invalid_json` "That JSON file can't be read: it isn't valid JSON."; `damaged` "Hearthkeep couldn't open that file. It may be damaged."; too big "That file is too big. Files can be up to 50 MB."; too many "Attach up to 5 files at a time."
- Produces (`cfb.py`): `cfb_stream_names(path: Path) -> set[str]` (header, DIFAT from the header's 109 entries, FAT chain of the directory; at most 4096 directory entries; `ValueError` on anything malformed).
- Produces (`store.py`): `CHAT_ID = re.compile(r"[0-9a-f]{32}")`; `ATTACHED_FILE_LINE = re.compile(r"Attached file: ([A-Za-z0-9_-]{1,32})")`; `@dataclass ChatFile(id, chat_id, name, kind, mime, size, status: Literal["ready","unchecked"], summary: dict | None, source: Literal["upload","folder"], created_at)`; `@dataclass(frozen=True) StagedFile(id, chat_id, tmp: Path)`; `class ChatFileStore: __init__(conn, data_dir: Path); files_dir(chat_id) -> Path; stage(chat_id, data: bytes) -> StagedFile; stage_copy(chat_id, src: Path, max_bytes: int = MAX_FILE_BYTES) -> StagedFile; record(staged, *, name: str, check: FileCheck, source, status="unchecked") -> ChatFile; discard(staged) -> None; set_status(file_id, status, summary: dict | None) -> None; list(chat_id) -> list[ChatFile]; get(file_id) -> ChatFile | None; path(file_id) -> Path | None`. `stage*` touch no database (worker threads); `record` inserts the row and moves the file in one `db.transaction`, removing the temp file on failure (same pattern as `ImageStore.record_upload`); `path` returns a file only inside that chat's `files/` folder.

Audit `file.attached` `{id, type, bytes}`.

- Dockerfile: pinned base by digest; `pip install --no-cache-dir --require-hashes -r requirements.txt`; `useradd --uid 10001 --create-home hk`; `/opt/hk` root-owned, not writable; `ENV PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=/opt/hk`; `USER 10001:10001`; `ENTRYPOINT ["python", "-I", "-B", "/opt/hk/hk_entry.py"]`.
- Container contract (`hk_entry.py <mode>`, mode `script` | `inspect` | `pages`): reads `/job/manifest.json` = `{"files": [{"id", "name", "kind", "path": "/data/<file_name>"}], "script_timeout_s": int, "args": {...}}`. `script` runs `python -B /job/main.py` (cwd `/tmp`, env `HOME=/tmp`, `PYTHONPATH=/opt/hk`) with stdout+stderr merged into a pipe; keeps the first 262,144 bytes in `/out/stdout.txt`, discards the rest, kills the child at `script_timeout_s`. `inspect` writes `/out/inspect.json` for `args.file`; `pages` renders `args.pages` of `args.file` at `args.dpi` (150) to `/out/pages/<n>.png`, longest side ≤ 2000 px. Always writes `/out/status.json` `{"exit_code": int|null, "timed_out": bool, "stdout_truncated": bool, "duration_ms": int}`, then writes an uncompressed tar of `/out` to its own stdout and exits 0.
- `results.jsonl` (one JSON object per line, appended by `hk`): `{"type":"value","name","value","unit","note","is_date","kind":"computed"|"document","page"}`; `{"type":"chart","title","spec"}`; `{"type":"table","name","columns","rows","row_numbers","note","total_rows"}`; `{"type":"file","name","member":"files/<name>"}`; `{"type":"cleaning","note"}`; `{"type":"section","name":"glance"}`.
- `hk` API: `files() -> list[dict]`; `read(file: str, *, sheet: str | int | None = None, header: int | None = None) -> pandas.DataFrame` (file by id or name; CSV: encoding utf-8-sig/utf-16/cp1252, delimiter sniffed from `, ; \t |`, decimal comma when the delimiter is `;` and values match `\d+(\.\d{3})*,\d+`, header row found among the first 20 lines as the first row with ≥ 2 non-empty cells followed by a consistent column count; Excel via `openpyxl` `read_only=True, data_only=True` or `xlrd`; JSON via `pandas.json_normalize`; sets `df.attrs["hk_first_data_row"]` to the 1-based file row of the first data row); `profile(file: str, *, sheet=None) -> None` (emits the `glance` section, values `rows`, `columns`, missing per column, and cleaning notes for mixed date formats, numbers stored as text, thousands separators, header not on line 1, negative amounts, duplicate rows; problem rows as tables); `result(name: str, value, *, unit: str | None = None, note: str | None = None) -> None` (numbers, numpy scalars, `date`/`datetime`/`Timestamp` → `is_date`, NaN/inf → `null` with note "not a number"); `document(name: str, value, *, page: int, unit: str | None = None) -> None`; `chart(spec: dict, *, title: str) -> None`; `bar|line|scatter(df, x: str, y: str, *, color: str | None = None, title: str, highlight: list[dict] | None = None) -> None` (Vega-Lite v6 specs with inline values, a `zoom` interval param bound to scales on line/scatter, a legend-bound point param with an opacity condition when `color` is set, and highlight items `{"x", "label"}` or `{"from", "to", "label"}` as rule/rect layers; `ValueError` over 5,000 rows); `table(name: str, df, *, columns: list[str] | None = None, note: str | None = None) -> None` (≤ 500 rows kept, `total_rows` true count, `row_numbers` = index + `hk_first_data_row`); `file(name: str, data: DataFrame | bytes | str) -> None` (`.csv` written UTF-8 with BOM, `.xlsx` via openpyxl, else bytes/text; names `[A-Za-z0-9][A-Za-z0-9._ -]{0,119}`); `cleaned(note: str) -> None`;
